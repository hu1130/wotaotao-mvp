# 全平台集成派工清单（DoR / DoD）

状态：V1.0  
覆盖范围：WBS 0.1～10.3 全部工作包  
依据：`项目文档/研发实施_V1.0/04_WBS工作量评估与研发分配表_V1.0.md`

## 1. 使用方法

本清单是派工和集成门禁，不是完成声明。每项从 `PLANNED` 进入 `READY` 前由 DRI 与复核人确认 DoR；进入 `DONE` 前由复核人/QA 确认 DoD 并附证据链接。

角色：A=DEV-A（产品、工作台、验收），B=DEV-B（Core、身份、账本、基础设施），C=DEV-C（Marketplace、订单、支付），D=DEV-D（CRM、外呼、微信），E=DEV-E（内容、自动化、OPC），F=DEV-F（数据、运营、观测），QA=专职测试。表中的“契约”指必须在 `packages/contracts/platform` 登记并由 SDK/Mock/测试共同使用的边界；`内部` 仍须有模块接口测试，但不一定公开为跨系统 API。

每张实际任务卡还必须填写：

```text
WBS ID / TPR ID / 分 PRD 功能 ID：
状态：PLANNED | READY | IN_PROGRESS | IN_REVIEW | DONE | BLOCKED
DRI / 复核 / QA：
契约版本 / Provider / Consumers：
代码 PR / 迁移 / 测试报告 / 截图或调用证据：
功能开关 / 回滚 / 已知限制：
```

## 2. 全局 DoR（每项都必须满足）

- 已关联 WBS、TPR、分 PRD 功能 ID；本轮尚未冻结的 PRD 设计规范不擅自补写为需求。
- 业务验收标准、P0/P1、非目标和边界明确；任务不超过 3 人日，超出已拆分。
- 依赖项达到表中要求，外部许可证、沙箱、测试账号或书面降级决定可用。
- 跨系统路径、Topic、Schema、错误码、幂等和样例已冻结；Provider 与 Consumer Owner 已确认。
- 数据 Owner、迁移/回滚、租户隔离、审计、秘密和合成数据方案明确。
- DRI、复核人、QA、集成窗口、功能开关和验收环境已经分配。

## 3. 全局 DoD（每项都必须满足）

- 代码、迁移、契约、SDK、Mock、Fixture、文档和变更记录按影响同步提交，无私有重复类型。
- 至少覆盖成功、输入失败、权限/状态失败；适用时覆盖跨租户、并发、幂等、重复回调/事件、超时、补偿和恢复。
- Provider/Consumer 契约测试、破坏性比较、typecheck、测试、build 和秘密扫描通过。
- 从空环境和升级环境验证；日志、指标、Trace、告警、审计、开关与回滚可用。
- 复核/QA 批准并合入 `integration`；真实证据路径已登记，未取得真实第三方证据的能力明确标记 `STUB_ONLY`。

```text
  -> 9 运维与安全 -> 10 联调/发布
```

- 4（CRM）可在 1 和契约冻结后与 2/3 并行；外呼/微信真实闭环受 0.3 和外部账号阻塞。
- 5 的内容/审核可与 Marketplace 并行，但真实发布必须使用真实商品/企业/额度事实。
- 6 可先用版本化事件 Fixture 开发，最终 DoD 必须切换为真实 Provider 事件重放。
- 7 可先完成账号/分配，现金收益必须等待 5.9 和 8.2/8.5。
- 8.2 账本内核可并行，但任何业务分录必须等待对应生产者事实与财务模板冻结。

## 16. 集成完成口径

单项 `DONE` 不等于系统完成；同一 SYS 的所有 P0 工作包、共享 WBS 9 门禁和相关 E2E 必须同时通过，才可称该系统“功能正常”。全部功能正常的口径是 WBS 0.1～10.3 所有 P0 均 DONE、条件式外部能力有真实证据且开启，或经老板/产品书面确认从范围中移除；不能用 Mock、人工记录或关闭开关冒充完成。
