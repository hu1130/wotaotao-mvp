# 2026-07-28 静音控制反馈生命周期修复

## 问题

用户直接说“静音”后，状态栏会很快被“静音中，喊{名字}唤醒我”覆盖，静音确认反馈没有完整展示和播放。静音期间喊数字人名字，例如“小丑”，解除静音反馈也可能被立即覆盖。

## 根因

后端静音路由和状态持久化已生效，问题发生在 avatar 前端状态机。`dialog_silence` 状态消息先于场景话术音频到达，`done` 又可能在浏览器音频真正入队或开始播放前到达。旧逻辑只看 `streamingAudioPlaying` 和 `streamingAudioQueue.length` 的瞬时值，误判反馈已播放完成，于是提前恢复长期静音状态或释放语音轮次。

解除静音 `active=false` 也没有使用同一套反馈保护，导致“已解除静音”话术和状态栏展示不稳定。

## 修改

- 为 `dialog_silence` 控制反馈增加前端生命周期状态：所属 turn、是否已收到音频、是否已收到 done、播放完成后的目标状态。
- 收到 `dialog_silence.responseText` 后先保护反馈文字，避免被 `llm_start`、清空 UI 或长期静音状态覆盖。
- 只有反馈音频实际入队并播放空闲后，才结束反馈保护；若 `done` 先到，会等待音频到达。
- 解除静音反馈复用同一生命周期，播完后短暂显示“已解除静音”；开启静音反馈播完后恢复“静音中，喊{名字}唤醒我”。
- 增加前端日志，记录反馈开始、音频收到、done 到达和超时兜底，方便现场定位时序问题。

## 影响

影响浏览器 avatar 实时语音前端的业务静音控制反馈展示和播放收尾。后端静音解析、静音状态存储、Omni 默认生成中断、固定语音播放规则和唤名解除规则不变。
