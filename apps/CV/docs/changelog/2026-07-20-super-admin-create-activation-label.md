# 2026-07-20 超级管理员新增激活码文案修正

## 问题

超级管理员页面把为租户再生成一个设备激活码的动作显示为“重置激活码”，容易被理解为旧激活码会立即失效或被替换。

## 原因

前端按钮、函数命名、API 日志和部署文档沿用了“重置”表述，但后端实际调用的是 `DeviceIdentityRepository.create_activation_code()`，会向 `device_activation_codes` 插入一条新的激活码记录，不会修改历史激活码状态。

## 修改方案

将超级管理员页面按钮、前端函数命名、后端日志和部署文档统一改为“新增激活码”。保留现有接口路径 `POST /activations` 和数据库写入语义。

## 影响

只影响超级管理员控制台展示、日志和文档说明。旧激活码仍按未使用、已使用或过期状态自然流转；新增激活码只会额外生成一条可交付给设备的一次性激活码。

## 验证

已执行 Node 语法检查、Python 编译检查，并确认代码中不再出现“重置激活码/激活码已重置”等误导性表述。
