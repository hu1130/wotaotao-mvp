# 2026-07-27 到场提醒硬匹配收紧

## 问题

现场用户说“我要来面试的。”后，数字人回复成到场提醒确认话术，并写入了人物到场任务。

## 原因

`person_memory.commands` 的目标到场提醒正则把“<目标> + 来 + <任意内容>”都识别为 `arrival_task`。因此“我要来面试的。”被解析成目标人名“我要”、提醒内容“面试的。”，随后进入人物记忆命令链路。

## 修改方案

目标到场提醒增加命令边界：

- 拒绝把“我、我要、我是、我们、你、他”等代词或第一/第二人称开头文本当作目标人名。
- 没有“待会儿/等会儿/一会儿/以后/之后/往后”等时间提示时，目标到场提醒必须在到场后明确包含“说、讲、喊、提醒、告诉、通知”等动作。
- 保留“待会儿小王来了，骂他两句”和“张三来了提醒他面试”等明确到场提醒。

追加收紧其他硬匹配边界：

- 音量澄清只在“调音量、调整声音、把音量...”等明确控制意图下触发，避免“你的声音很好听”“声音怎么样”被当成调音量。
- “听不清、没听懂、听不见”等听觉澄清话术不再触发“你刚才说了什么”类对话回忆。

## 影响

影响语音链路中的个人记忆命令、音量动作和对话回忆解析，避免普通来访、声音评价、听不清反馈误触发有副作用或上下文类场景。自我到场提醒、人脸录入、业务静音、明确音量动作和企业 RAG 路由不变。

## 验证

新增并运行人物记忆命令测试，覆盖“我要来面试的。”、“我是来面试的。”、“我来面试的。”、“我要来咨询的。”和目标到场提醒正例。

追加运行语音硬匹配组合测试，覆盖声音评价、明确音量澄清、听觉澄清和既有 RAG/静音/人脸录入规则。
