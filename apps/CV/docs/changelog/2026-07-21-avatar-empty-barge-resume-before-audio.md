# 2026-07-21 数字人回答前被空抢话后的续答恢复

## 问题

数字人已经进入思考或准备回答阶段，但还没有播出第一个字时，如果被用户声音打断，后续空 ASR 结束后不会继续刚才的回答。

## 原因

空抢话恢复只保存了已播放句子、音频队列文本或已生成的回答片段。若打断发生在 `llm_start` / `tts_start` 早期，浏览器端可能还没有任何回答文本或音频 item，恢复结构为空，空 ASR 后只能回到待机。

## 修改

- 空抢话恢复结构新增上一轮用户问题 `promptText`。
- 取消待回答轮次时，即使还没有回答文本，只要有上一轮用户问题，也会保留恢复上下文。
- 空 ASR 后优先接着播已捕获的回答片段；如果没有回答片段，则重新生成上一轮问题的回答并播报。
- 恢复播报期间不再二次捕获空抢话恢复，避免“刚才我接着说”提示词被当成原回答反复恢复。
- 捕获恢复文本时剥离“刚才我接着说 / 刚才还没来得及回答，我继续说”等恢复提示前缀，只保留真实回答内容。
- 恢复续播时区分“被打断的来源轮次”和“当前负责播放的轮次”，避免空 ASR 结束后 `activeVoiceTurnId` 已切换导致重新生成的回答被当成过期结果丢弃，并确保 busy 状态能释放。
- 数字人页和漩涡运行页同步更新 `avatar.js` 版本戳，避免浏览器继续使用旧状态机。
- 恢复 TTS 音频对象创建后增加 `loadedmetadata` / `canplay` / `playing` / `error` 客户端日志，并增加播放启动 watchdog；若浏览器拿到音频但 5 秒内没有进入播放态，会主动清理音频锁和 busy 状态，避免页面停在 voice mode。
