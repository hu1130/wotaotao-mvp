# 2026-07-20 显式记忆全量上下文与个人每日总结知识库

## 问题

用户明确说“记住……”的内容和普通聊天中自动提炼出的事实混在同一个 top-k 记忆窗口里。显式记忆超过 6 条后，虽然不会丢失，但不一定全部进入数字人上下文；普通聊天也缺少按天沉淀的个人知识库总结。

## 原因

旧链路只有 `person_memory_facts` 一层：显式记忆、worker 自动事实提炼、上下文检索都共用同一套排序。这样无法表达“用户指定记住的内容必须优先、全量可见”，也无法把普通沟通沉淀为按天可检索的个人知识条目。

## 修改方案

- 将 `extractor_version='explicit-user-command'` 的事实识别为显式记忆。
- 上下文构建时单独读取显式记忆，并全量放入 `<person_memory>`，不受普通记忆 top-k 和字符预算裁剪。
- 普通自动提炼事实继续保留，但普通事实检索排除显式记忆，避免重复。
- 新增 `person_memory_daily_summaries` 表，按 `person_id + summary_date` 保存每日总结、tokens 和 embedding。
- `memory-worker` 空闲时定期扫描昨天及更早未总结的完成轮次，调用 agent 生成每日总结，生成 embedding 后写入个人知识库。
- 如果某天没有值得长期保存的信息，写入 `status='empty'` 标记，避免反复调用 agent 总结同一天。

## 影响

数字人每轮上下文现在包含三层：

1. 用户明确要求记住的内容：全部进入上下文，优先级最高。
2. 普通长期事实和人物画像：保留原有低延迟提炼能力，按 top-k 控制上下文体积。
3. 个人知识库日总结：由 worker 按天总结普通沟通并 embedding，后续可按语义检索进入上下文。

企业知识库不受影响；公司业务问题仍走企业知识库，个人沟通背景走人物记忆/个人知识库。

## 验证

已新增并通过人物记忆单测，覆盖显式记忆全量上下文、每日总结表迁移、每日总结 embedding 写入和空总结跳过标记。
